# End-to-end tests

`npm run test:e2e` builds the app (`npm run build`), serves it with `vite preview` on port 4173 and runs
the specs below in Chromium with the **real** Stockfish 19 lite WASM engine. Lichess and Chess.com are
replaced by fakes that serve the files in `e2e/fixtures/`; every other external request is blocked, and
each test fails if one was attempted, if the page threw an uncaught error, or if the page reported a
Content-Security-Policy violation (the build's CSP `<meta>` is enforced). A preview server already
running on port 4173 is reused. With `CI` set, the suite does not build: it serves the existing `dist/`
(CI's Build step has just built and checked it), so run `npm run build` first if you set `CI` locally.
`E2E_WEBKIT=1` adds a WebKit project (its browser must be installed). Specs under `e2e/live/` (real
APIs) are not part of this suite.

The whole suite takes about two minutes (the real-engine analyses dominate).

| Spec | What it covers |
| --- | --- |
| `lichess-journey.spec.ts` | onboarding with a Lichess username → sync progress → analysis → the planted blunders found; leak detail (arrows, lines, master → Mastered tab → restore); training (habit refuted, typed SAN, correct board move graded); backup download → delete all data → restore; re-analysis from an empty eval cache with 3 engines and with 1 engine reproduces every verdict of the first (300 games, then 400) run |
| `chesscom.spec.ts` | onboarding with a Chess.com username: monthly archives newest first, variant games skipped, planted blunders found |
| `pgn-upload.spec.ts` | Quick preset chosen in Settings, PGN upload with “Which of these is you?”, import summary, analysis |
| `training-promotion.spec.ts` | a restored backup with the Lasker Trap (7…fxg1=N+): promotion picker, Escape, habit (=Q) refuted, =N accepted |
| `network-error.spec.ts` | Lichess unreachable: the friendly error with “Upload a PGN file instead”, nothing stored. Only the game export failing: the dashboard's error banner, “No games yet” (not “no mistakes”), no backfill retry, and the PGN upload in Settings |
| `offline.spec.ts` | after a first visit, with the network cut: app shell, engine (JS + WASM) and example report from the service worker cache; a new training move checked by the engine |
| `mobile.spec.ts` | 390 × 844 touch: bottom tab bar, leak list → leak screen → next → back, training board, More sheet, no horizontal scroll |
| `demo.spec.ts` | the page carries its CSP; “See an example report” loads `public/demo/demo.json`, makes no request, and “Analyze my own games” removes it |

`support/` holds the shared pieces: `network.ts` (the fakes), `csp.ts` (collects the page's
`securitypolicyviolation` events), `app.ts` (test fixtures, IndexedDB peeks used to wait for background
jobs, chessground board helpers), `session.ts` (one browser context for a serial journey),
`fixtures.ts` (fixture loading and the planted mistakes' URL ids) and `backup.ts` (the hand-made
promotion backup).

A note on CORS: a response fulfilled by Playwright skips the browser's CORS check, so a request blocked
by CORS (or an ad-blocker, or being offline) is simulated the way the page experiences it — `fetch()`
rejects with a `TypeError` — by aborting the request.

## Fixtures

Everything in `e2e/fixtures/` is generated by **`scripts/gen-fixtures.mjs`** (`npm run gen:fixtures`)
and committed. It is a Node port of the engine benchmark's Python generator (`gen_games.py`): the same
model of a player with a fixed repertoire, planted habitual mistakes and repeated habits elsewhere, built
on chessops (the app's chess library) and the vendored opening TSVs in `data/openings/`. A Node port
was chosen over committing the Python script so contributors need nothing beyond `npm install`
(no Python, no python-chess), and the generator shares the app's notion of a position key. It uses its
own seeded PRNG (sfc32), so its games differ from the Python generator's, but the output is
byte-identical for a given seed: `scripts/gen-fixtures.test.mjs` regenerates everything and compares it
with the committed files, and recounts the manifest's ground truth from the games.

| File | Content |
| --- | --- |
| `lichess-games.ndjson` | `GET /api/games/user/TestHero` — 400 games, newest first (Lichess NDJSON) |
| `lichess-user.json` | `GET /api/user/TestHero` |
| `chesscom/player.json`, `archives.json`, `YYYY-MM.json` | Chess.com PubAPI for `TestHero`: 150 games over four monthly archives, plus three games the app must skip (Chess960, bughouse, knight odds; taken from `src/sources/__fixtures__`) |
| `upload.pgn` | 120 over-the-board games of “Hero, Test” (no site links, so stored as PGN games) plus a Chess960 game |
| `manifest.json` | seeds, the repertoire, and per set the planted deviations: position (FEN / EPD), move, kind (`hangs_material` with the piece, or `offbook`), and `times_reached` / `times_played` — distinct games in which the hero reached the position / played the move there (first visit per game, any game mode), the same counting the app uses |

The e2e tests assert against the manifest: every planted deviation that hangs a piece and was played in
at least three games must be found as a blunder with exactly those counts.

## Demo dataset

`public/demo/demo.json` (the example report) is built by `npm run build:demo` (`scripts/build-demo.mjs`
runs `scripts/build-demo.ts` through Vite's module runner): 500 games of “Demo Player” from the same
generator, imported as PGN and analysed by the real pipeline in Node (fake-indexeddb, the vendored
engine through `src/engine/nodeWorker.ts`, standard preset), plus a short training history; exported
as a v3 backup without evals (about 450 KB). The output is reproducible, whatever the number of engines
(`-- --workers N`). Rebuild it after changing the engine, the analysis or the classification.
